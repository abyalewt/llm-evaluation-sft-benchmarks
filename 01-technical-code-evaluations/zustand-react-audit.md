## 2. The User Prompt

> "Explain how client-side state management works in React using Zustand. Provide a concise code example demonstrating how to define a store with a counter and an asynchronous action to fetch user data, and explain how a component subscribes to just that counter state without unnecessary re-renders."

---

## 3. Candidate Outputs

### Candidate A

```javascript
import { create } from 'zustand';

const useUserStore = create((set) => ({
  count: 0,
  user: null,
  increment: () => set((state) => ({ count: state.count + 1 })),
  fetchUser: async (id) => {
    const res = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
    const data = await res.json();
    set({ user: data });
  },
}));

function CounterDisplay() {
  const count = useUserStore((state) => state.count);
  return <div>Count: {count}</div>;
}

function CounterDisplay() {
  const count = useUserStore.useSelector((state) => state.count);

4. Quality Audit & Forensic Evaluation
Verdict
Response A is rated Much Better than Response B due to critical API hallucinations and architectural concept blending in Response B.

Constraint & Technical Audit
Store Creation & Async Action: Both models correctly implement store state and async updates using set.

State Subscription Adherence: Response A uses valid Zustand selector syntax. Response B fabricates sub-methods and component wrappers.

Syntax Validity: Response A runs out-of-the-box. Response B raises fatal runtime errors.

Forensic Evidence
Fabricated Primitive 1: Response B claims a <ZustandProvider> component is required. Zustand is inherently provider-less; this blends patterns from Redux (<Provider>) or the React Context API.

Fabricated Primitive 2: Response B invokes useUserStore.useSelector(...). No .useSelector method exists on custom hooks generated by create().

Operational Impact
Executing Response B's code in a standard React environment results in an immediate crash:

Plaintext
TypeError: useUserStore.useSelector is not a function
Because Response B outputs non-functional code while presenting it as authoritative, Response A is decisively preferred.
```
